# Downloads (`smolf export`)

`smolf export series-csv` turns a finished publish into the download bundle: `series.csv` (one row per `series.json` scene, POOR scenes included), `series_monthly.csv` (one row per `monthly` entry), `README.txt` (English, ASCII), `LEEME.txt` (Spanish, UTF-8), `reservoir_outline.zip` (the reservoir polygon as a shapefile, since v0.11.0) and `SHA256SUMS` (over the other five, `sha256sum -c` format). It reads `publish.json`, `series.json` and `latest.json` from the publish dir plus the committed AOI polygon, and never touches the network. Before writing, it checks that `publish.json` passes its schema, that the other two hash to their `publish.json` entries and pass theirs, and that all three name the same run. The output directory is replaced atomically. Refusals exit 2 with one `refused: …` line on stderr, an empty stdout, and nothing written. `smolf export maps` (since v0.11.0) writes one classified GeoTIFF per scene with figures into `outputs/maps/`, built from the run behind the publish and the scene cache, plus `index.csv`, `README.txt` and `SHA256SUMS`. Since v0.14.0 it is incremental across runs: it keeps the previous export's map of every scene whose map inputs are unchanged (same `map_key`, `smolf_version` and `config_hash` in the old `index.csv`, file hash intact), whatever run it came from, and builds only the rest. It prints no per-scene line. It refuses the same way. `smolf export viewer` (since v0.12.0) writes the per-date viewer archive into `outputs/viewer/`: one `<date>_<item_id>/` folder per scene with figures, holding `photo.webp` (the true-colour photo, read from the item's COGs over the network), `classified.webp` (the published class map, lossless) and `figures.json` (the scene's `series.json` figures, hectares and percent per class, and wet biomass), plus `index.json`, `README.txt` and `SHA256SUMS`. Since v0.13.0 it is incremental across runs: a folder of the previous export is kept when its map inputs (`map_key`) and figures are unchanged, whatever run it came from, and a rebuilt folder reuses its photo when its `photo_key` is unchanged. It refuses the same way. All three are outside the data contract (`docs/downloads.md`).

## Sub-features

- `export-default` writes the bundle from the default publish dir into `$SMOLF_DATA_DIR/outputs/downloads/`.
- `export-again` rewrites the same bundle byte for byte.
- `export-out` reads an explicit `--from` and writes an explicit `--out`.
- `export-tamper` refuses a publish whose `series.json` no longer matches `publish.json`.
- `export-old-contract` refuses a publish from an older minor contract that lacks a property the packaged schemas require.
- `export-no-publish` refuses a `--from` with no `publish.json`.
- `export-foreign` refuses an `--out` that holds a file the export does not own.
- `export-inside` refuses an `--out` inside the publish dir.
- `maps-default` writes every scene map from the default publish dir into `$SMOLF_DATA_DIR/outputs/maps/`.
- `maps-again` re-runs it with every map kept: seconds, empty stderr, every file byte-identical.
- `maps-rebuild` rebuilds only a map whose file was damaged, byte for byte.
- `maps-newrun` exports a publish of another run over the existing maps and keeps every unchanged one.
- `maps-out` writes them to an explicit, empty `--out`, byte-identical to the incremental export.
- `maps-inside`, `maps-tamper` and `maps-no-run` refuse an `--out` inside the publish dir, a tampered publish, and a publish whose run is not in the data dir.
- `maps-foreign` refuses an `--out` that holds a file the export does not own.
- `viewer-default` writes the viewer archive from the default publish dir into `$SMOLF_DATA_DIR/outputs/viewer/`.
- `viewer-again` re-runs it with nothing to rebuild: every folder kept, every file byte-identical.
- `viewer-rebuild` rebuilds only a folder whose file was removed, byte for byte.
- `viewer-inside`, `viewer-tamper` and `viewer-no-run` refuse an `--out` inside the publish dir, a tampered publish, and a publish whose run is not in the data dir.
- `viewer-foreign` refuses an `--out` that holds a file the export does not own.
- `viewer-newrun` exports a publish of another run over the existing archive and keeps every unchanged folder, photos included.

## How to get to it (user POV)

- Run `smolf export series-csv [--from <publish dir>] [--out <dir>]` after `smolf publish`.
- Run `smolf export maps [--from <publish dir>] [--out <dir>]` after `smolf publish`, in the data dir that holds the published run and its scene cache.
- Run `smolf export viewer [--from <publish dir>] [--out <dir>]` after `smolf publish`, with the same data dir as `maps` and the network.

## Gotchas

- The input checks run before any `--out` check, so a bad `--out` is reported only when the publish itself is valid. A tampered `series.json` hits the hash check before the schema check.
- `exported:` echoes `--out` as given (normalised by `Path`: no trailing slash or `./`), not resolved.
- The bundle files are not in `publish.json`. Export never changes the publish, so its `sha256sum -c` still passes afterwards.
- `--out` refusals for symlinked or several-previous dirs reuse publish's wording (`… several previous publishes remain …`).
- After upgrading smolf, re-run `smolf publish` before exporting: export validates against the packaged schemas, so a publish from an older minor release (3.3.0 lacks `stage_area_curve` and `exposed_bed_example`) is refused with `series.json fails its schema`. The message names the file without its path, unlike the hash refusals.
- `export maps` resolves the run as `$SMOLF_DATA_DIR/outputs/series/<run_id>` whatever `--from` says, and builds every map it does not keep through the publish's own map builder, so its other refusals (`run … is not complete`, `… series_sha256 … differs from the publish series_sha256`, `cache sha256 of <item> …`, `re-classified <item> differs from the run …`, `map of <item> differs from series.json …`) need an edited run dir or a changed cache. Never tamper with the shared cache; the test suite covers them.
- `export maps` checks `--out` for foreign files only when it writes, after every map is kept or built, unlike `series-csv` and `publish`, which check before any work. The inside-the-publish check runs first. Over an empty `--out`, or one written by another smolf version or config, that means a full build (about 6 min) before the refusal.
- `export maps` prints nothing per scene, so kept versus built shows only in the wall time, the guard lines (one per rebuilt scene that trips the radiometry guard) and the hashes. The first export after any smolf upgrade (or settings change) rebuilds every map once, because each `index.csv` row must carry the running `smolf_version` and `config_hash`; an `index.csv` from 0.13.0 or earlier has no keys at all.
- POOR scenes have no figures and get no map, so `index.csv` has fewer rows than `series.csv`. The viewer skips them the same way.
- Like `export maps`, `export viewer` checks `--out` for foreign files only when it writes, after every scene is built or kept. Over an archive whose folders are all kept, `viewer-foreign` refuses in seconds (5 s on 2026-11-27 and 2026-11-25); over an empty `--out`, or one written by another smolf version or config, it would rebuild everything first (20–35 min).
- `export viewer` keeps a folder only when the existing `index.json` has the running `smolf_version` and `config_hash`, the folder's three files hash to that index, its `map_key` equals the scene's current one, and its `figures.json` rebuilds byte for byte from the current `series.json` under the old `run_id`. Then only `figures.json` is rewritten with the new run. Otherwise the map and figures are rebuilt, and the photo is copied when `photo_key` (item, backend, bounds, reservoir polygon) is unchanged (`built … (photo kept)`). The first export after any smolf upgrade (or settings change) rebuilds every folder once, photos included (20–35 min), because `index.json` must carry the running `smolf_version` and `config_hash`.
- `$V hectares` reads GeoTIFFs only. Check the viewer's per-class hectares in `figures.json` against `series.json`, or against the same scene's map from `export maps`.
- The daily job runs none of the three exports (see daily-job.md). A new publish leaves the old bundle, maps and viewer archive in place until each export runs again.
