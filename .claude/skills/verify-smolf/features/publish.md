# Publish the contract

`smolf publish` turns one complete, clean series run (named with `--run <id>`, or the newest with `--latest`) into the versioned data contract for downstream consumers: `latest.json`, `series.json`, `publish.json` (sha256 of every other file), the latest scene's map as `map/<date>_<item_id>.tif` plus a display `.png`, the 2024-06-09 exposed-bed example's two display maps (`map/<date>_<item_id>.raw.png`, classes 0–4, and `map/<date>_<item_id>.png`, classes 0–5; no GeoTIFF), and Sentinel-2 true-colour photos read from the items' COGs at publish time: `image/<date>_<item_id>.webp` (the latest scene) and one `image/clipped/<date>_<item_id>.webp` per `same_month` year with a scene, all RGBA, gamma 1.6, clipped to the reservoir and transparent on no-data pixels. Every publish needs the network for those photos, even with a warm cache. The output directory is replaced atomically. Refusals exit 2 with one line on stderr and keep the previous contract. Since v0.10.0 they include a committed stage–area curve whose sha256 differs from the run manifest (checked on every publish) and an example scene that fails the latest map's checks or is not on its grid (checked before the photo reads). After the `--run`/`--latest` check (and a broken-symlink `--out` check), publish recovers its own crash leftovers next to `--out` (a lone `.<name>.previous-*` is renamed back, allowlisted `.<name>.staging-*` dirs are removed), even when it then refuses. A contract that fails its own schema exits 1 with one `error:` line. A photo or map that fails its guard also exits 1, but as an uncaught Python traceback, not one line.

## Sub-features

- `publish-default` publishes the newest complete run (`--latest`) to `$SMOLF_DATA_DIR/outputs/publish/`.
- `publish-no-choice` refuses when neither `--run` nor `--latest` is given.
- `publish-both` refuses when both `--run` and `--latest` are given.
- `publish-out` publishes to an explicit `--out` directory.
- `publish-empty-out` accepts an existing empty `--out` directory.
- `publish-crash-recover` recovers from a crash between the swap's two renames.
- `publish-several-previous` refuses when `--out` is missing and several previous publishes remain.
- `publish-link` publishes through a symlinked `--out` into its target and keeps the link.
- `publish-out-file` refuses an `--out` that is a regular file.
- `publish-refuse-foreign` refuses an `--out` that holds unrelated files.
- `publish-unknown-run` refuses a `--run` id that does not exist.
- `publish-read-fail` refuses, keeping the previous contract, when a true-colour photo cannot be read.
- `publish-again` republishes the same run byte for byte.

## How to get to it (user POV)

- Run `smolf publish (--run <run_id> | --latest) [--out <dir>]`.

## Driving it with smolf-verify

Preconditions:

- A complete, clean series run in this run's data dir (see series-build.md). The latest scene's cache file must still match the run's recorded hash.
- `doctor --net` shows 200 for Earth Search: each photo's STAC item comes from the backend that served that scene (its record's `backend_used`), which is Earth Search for the latest scene and the `same_month` scenes of current runs. Doctor does not probe the COG hosts the bands are read from.
- Each publish that writes takes about 1.5–5 min for 11 photos: the latest scene plus 10 `same_month` years. Measured at v0.12.0: 79–189 s on 2026-11-25; at v0.11.0, 69–110 s on 2026-11-23; at v0.10.0, 106–113 s and later 194–285 s on 2026-11-22, 77–181 s on 2026-11-21. The photo reads dominate and their speed varies with the COG hosts; since v0.10.0 each publish also re-classifies the cached example scene. The recipe makes 7 writing publishes, so budget about 15–35 min.

- **Default.** Run `$V run "$RUN" publish-default -- publish --latest`. `.rc` `0` and `published: $RUN/data/outputs/publish/latest.json`. Copy `latest.json` and `publish.json` into the evidence. `latest.json` has `current_level.date` equal to the refreshed record's last day with a level, and `current_level.levels_sha256` equal to `sha256sum $RUN/data/hydro/ENDHD.csv`. Every hash in `publish.json` matches `sha256sum` of the file it names (`jq -r '.files[]|"\(.sha256)  \(.path)"' publish.json | sha256sum -c`), and every file but `publish.json` is listed there. `latest.json` `image` passes `jq -e '.image.path == "image/\(.date)_\(.item_id).webp" and .image.bounds == .map.bounds and .image.attribution == "Copernicus Sentinel data \(.date[:4])"'`, and that WebP has 4 bands (RGBA, alpha 0 outside the reservoir) of the `map.png` size. All three JSON files carry `schema_version` `3.4.0` (contract 3.4.0, first released in `v0.10.0`, unchanged in `v0.11.0` and `v0.12.0`) and the publishing release's `smolf_version` (`0.12.0` at `v0.12.0`, the current tag); `publish.json` lists 17 files for run `20261125T011151` (v0.12.0, 2026-11-25; also for `20261123T022429`, `20261122T162250` and `20261121T021625`), four of them under `map/` (the latest `.tif` and `.png`, the example's `.png` and `.raw.png`); `latest.json` has `reservoir_outline` of `type` `MultiPolygon`; in `series.json`, any scene with `bed_applied: false` has `removed_ha` and every `*_corrected` field `null`. Every scene of `series.json` and `latest.json` has `display_status`: `HIDDEN` when `quality_light` is not `GOOD` or `hyacinth_corrected_ha` is `null`, else `LOWER_BOUND` when `valid_frac` < `latest.json` `constants.frac_publishable` (`series.json` has no `constants`), else `FULL`. Check it with `jq '[.scenes[] | select((.quality_light != "GOOD" or .hyacinth_corrected_ha == null) != (.display_status == "HIDDEN"))] | length' series.json` (expect `0`) and, for `LOWER_BOUND`, `jq --argjson f "$(jq .constants.frac_publishable latest.json)" '[.scenes[] | select(.display_status != "HIDDEN") | select((.valid_frac < $f) != (.display_status == "LOWER_BOUND"))] | length' series.json` (expect `0`). Every scene's `display_ha` is `null` exactly when `hyacinth_corrected_ha` is, and otherwise its `dense + interface` equals `total`: `jq '[.scenes[] | select((.display_ha == null) != (.hyacinth_corrected_ha == null) or (.display_ha != null and .display_ha.dense + .display_ha.interface != .display_ha.total))] | length' series.json` (expect `0`). `latest.json` `constants.green_max_ha` is `378.53` and `red_min_ha` `630.88`. `series.json` `monthly` runs without gaps from the first scene's month to the last's, and each entry's `n_scenes` equals that month's non-`HIDDEN` scenes: `jq '[.monthly[] as $m | select($m.n_scenes != ([.scenes[] | select(.date[:7] == $m.month and .display_status != "HIDDEN")] | length) or (($m.n_scenes == 0) != ($m.median_ha == null)))] | length' series.json` (expect `0`). `latest.json` `same_month` is `null` only when no scene is `FULL`; otherwise its `month` (an integer, 1–12, so compare with `.date[5:7]|tonumber`) is the month of the last `FULL` scene in `series.json`, its `years` run from the first scene's year to that scene's year, every year with `n_scenes` > 0 has a `scene` and an `image` whose `path` exists under `image/clipped/` and is listed in `publish.json`, and each clipped WebP has 4 bands (`gdalinfo` or rasterio) of the `map.png` size. Every year carries a boolean `featured`: the last year is always featured, at most four are, and every featured year has a `scene` and an `image` (`jq '[.same_month.years[] | select((.featured|type) != "boolean" or (.featured and (.scene == null or .image == null)))] | length' latest.json`, expect `0`). For run `20261125T011151` (built at `v0.12.0`, 472 scenes) the featured years are `[2017,2021,2025,2026]` (`jq -c '[.same_month.years[] | select(.featured) | .year]' latest.json`, measured 2026-11-25; unchanged from runs `20261123T022429`, `20261122T162250`, `20261121T021625`, `20261120T025846`, `20261119T200232`, `20261119T184404` and `20261106T154111`). `series.json` `stage_area_curve` gives `jq -c '.stage_area_curve|[(.stage_m|length),(.area_ha|length),(.area_ha_p2_5|length),(.area_ha_p97_5|length),.stage_min_m,.stage_max_m,(.anchors|map(.stage_m)),.sha256[:16]]' series.json` → `[400,400,400,400,2003.99,2018.5,[2003.16,2018.0,2020.0],"31d20fef788ac782"]`, and that sha256 equals `sha256sum $RUN/checkout/data/hydro/stage_area_curve.csv` and the run manifest's `.inputs.stage_area_curve_csv`. `exposed_bed_example` gives `jq -c '.exposed_bed_example|[.date,.item_id,.level_m,.margin_m,.expected_bed_ha,.hyacinth_raw_ha,.hyacinth_under_haze_ha,.removed_ha,.hyacinth_corrected_ha,.dense_corrected_ha,.interface_corrected_ha]' series.json` → `["2024-06-09","S2A_14QMH_20240609_0_L2A",2004.6,2005.54,696.8,434.35,1.9,418.69,15.66,4.2,11.46]`; without `margin_m`, `expected_bed_ha`, `map_raw` and `map_corrected` it equals that date's `scenes` entry (`jq '(.exposed_bed_example|del(.margin_m,.expected_bed_ha,.map_raw,.map_corrected)) == first(.scenes[]|select(.date=="2024-06-09"))' series.json`, expect `true`), and its `map_raw.path` / `map_corrected.path` are `map/<date>_<item_id>.raw.png` / `.png` with `bounds` equal to `latest.json` `map.bounds`. Both example PNGs have the `map.png` size; counting `#d0573a` (class 5) opaque pixels with the checkout's Python (PIL, numpy) gives `0` in the raw one and `41768` in the corrected one (the native grid has 41869 = `removed_ha` × 100; the web-Mercator warp loses 0.24 %). The three JSON files also validate against the `v0.9.0`, `v0.6.0` and `v0.5.0` schemas (`git show <tag>:src/smol_frontier/schemas/<name>.schema.json`): 3.1.0 only added an optional field, 3.2.0 changes no field, 3.3.0 only adds `hyacinth_under_haze_ha`, and 3.4.0 only adds `stage_area_curve` and `exposed_bed_example`.
- **No choice.** Run `$V run "$RUN" publish-no-choice -- publish`. `.rc` `2`, `.err` is `error: pass --run <run_id> or --latest`, `.out` is empty, and the publish dir is unchanged.
- **Both flags.** Run `$V run "$RUN" publish-both -- publish --run x --latest`. `.rc` `2`, `.err` is `error: pass either --run or --latest, not both`, `.out` is empty.
- **Explicit out.** Run `$V run "$RUN" publish-out -- publish --latest --out "$RUN/data/alt-publish"`. `.rc` `0`, and the files land there, not in the default directory.
- **Empty out.** `mkdir -p "$RUN/data/empty"`, then run `$V run "$RUN" publish-empty-out -- publish --latest --out "$RUN/data/empty"`. `.rc` `0`, and the five contract entries (`image`, `latest.json`, `map`, `publish.json`, `series.json`) land there, with the four map files above under `map/`.
- **Crash recovery.** Publish once with `$V run "$RUN" publish-crash-recover -- publish --latest --out "$RUN/data/pub"`. Then fake a crash mid-swap: `mv "$RUN/data/pub" "$RUN/data/.pub.previous-.pub.staging-crash1"`, `mkdir "$RUN/data/.pub.staging-crash1"` and copy `latest.json` into it. Run `$V run "$RUN" publish-crash-recover -- publish --latest --out "$RUN/data/pub"`. `.rc` `0`, `pub` holds a fresh contract, and no `.pub.*` entry remains. Repeat the fake crash and run `-- publish --run nope --out "$RUN/data/pub"`: `.rc` `2` (`refused: unknown run: nope`), yet `pub` is restored with the same `latest.json` (same sha256) and the staging dir is gone.
- **Several previous.** With `pub` missing and two dirs `.pub.previous-.pub.staging-a1` and `.pub.previous-.pub.staging-b2`, run `$V run "$RUN" publish-several-previous -- publish --latest --out "$RUN/data/pub"`. `.rc` `2`, `.err` `refused: --out $RUN/data/pub is missing and several previous publishes remain (.pub.previous-.pub.staging-a1, .pub.previous-.pub.staging-b2); restore one by hand`, and both dirs are left as they were.
- **Symlinked out.** After Explicit out, run `ln -s alt-publish "$RUN/data/link"`, then `$V run "$RUN" publish-link -- publish --latest --out "$RUN/data/link"`. `.rc` `0` (`published: $RUN/data/link/latest.json`), `link` is still a symlink, and the files are refreshed in `alt-publish`.
- **File as out.** `touch "$RUN/data/afile"`, then run `$V run "$RUN" publish-out-file -- publish --latest --out "$RUN/data/afile"`. `.rc` `2`, `.err` `refused: --out $RUN/data/afile exists and is not a directory`.
- **Foreign out.** `mkdir -p "$RUN/data/foreign" && echo x > "$RUN/data/foreign/notes.txt"`, then run `$V run "$RUN" publish-refuse-foreign -- publish --latest --out "$RUN/data/foreign"`. `.rc` `2`, `.err` `refused: --out $RUN/data/foreign is not a previous publish (no publish.json or files outside the allowlist)`. `notes.txt` is still there.
- **Unknown run.** Run `$V run "$RUN" publish-unknown-run -- publish --run nope`. `.rc` `2`, `.err` `refused: unknown run: nope`.
- **Photo read failure.** Check that the latest scene was served by Earth Search (`latest.json` `item_id` like `S2A_14QMH_20261108_0_L2A`, not `S2B_MSIL2A_…`); otherwise blocking Earth Search does not reach its photo. Hash the default `publish.json`, then run `$V run "$RUN" publish-read-fail --block-host earth-search.aws.element84.com -- publish --latest`. `.rc` `2`, `.out` empty, and `.err` is one line starting `refused: true-colour image of <item_id> could not be read: ` that names `earth-search.aws.element84.com`. The default `publish.json` keeps its hash and no `.publish.*` entry remains in `$RUN/data/outputs/`. The reason is cut at 300 characters, which drops the `blocked by smolf-verify` marker, so the proof the block caused it is the host in the message plus a clean publish of the same run without `--block-host` (Default or Determinism).
- **Determinism.** Save `jq -S 'del(.generated_utc)' publish.json` and copies of `latest.json` and `series.json`, run `$V run "$RUN" publish-again -- publish --latest`, and compare: `latest.json` and `series.json` are byte-identical, and the saved `publish.json` view is identical, so both maps, the two example PNGs and every WebP kept their sha256 too.

## Gotchas

- `refused: scene <item> has no hyacinth_under_haze_ha: the run predates the haze rescue (contract 3.3.0)` means the run was built before v0.8.0. Rebuild it with `smolf series build`.
- The download bundle (`smolf export series-csv`), the per-scene maps (`smolf export maps`) and the per-date viewer archive (`smolf export viewer`, since v0.12.0) are derived from a publish (see export.md). Publish refreshes none of them.
- `smolf_version` is the release that publishes, not the one that built the run, so republishing the same run after an upgrade changes `latest.json`, `series.json` and `publish.json` (and nothing else). The Determinism step compares two publishes of one release.
- `refused: run … was built from a dirty tree` means the checkout was dirty during `series build`. Fix the checkout and rebuild. Never edit the manifest.
- `--latest` takes the newest complete run by id. A later run in the same data dir (for example the reference-only run of a resume test) wins over the `--extend` run, and `latest.json` then shows the reference series' last scene. Use `--run <id>` when the data dir holds more than the run you mean.
- `current_level` has `date`, `level_m` and `levels_sha256`, read from the data-dir record when it exists, else the committed one. It is `null` when there is no record with a level.
- Publishing the same run with the same level record gives byte-identical `latest.json` and `series.json`, and the same map and photos while the STAC items are unchanged. After a level refresh, only `current_level` (and `publish.json`) change. A backend that reprocesses an item changes that photo's sha256 but no figure.
- `boa_offset_applied looks wrong … using 0.0` on stderr of a successful publish is the radiometry guard on one photo (one line on every publish of 2026-11-21 and 2026-11-22), not a failure. Read `.rc`.
- The curve-mismatch and example-grid refusals cannot be driven from a read-only `--ref` checkout without editing committed inputs; the test suite covers them. Report them as not driven.
- The map rebuild re-reads the cached scene and checks its hash; since v0.10.0 the same holds for the 2024-06-09 example scene, before any photo read. A cache file changed since the build makes publish refuse. A missing cache file is re-downloaded by its exact item id first (network).
- The photos bypass the cache and are always read over the network, so a STAC or COG outage refuses the publish with exit 2 (retry later) even when the map could be built.
- `latest.json` is the last `ok` scene with figures, not the last scene in `series.json`: a trailing POOR scene (2026-11-11 on 2026-11-18) shows up in `series.json` as `HIDDEN` while `latest.json` keeps the scene before it.
